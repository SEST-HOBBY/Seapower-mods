v1.27.2 outer-aileron hinge-frame correction
----------------------------------------------
- Corrected the v1.27.1 regression where removing all four static control-surface
  rotations also removed the source hinge frame required by the two outer
  ailerons. This made the ailerons detach or swing away when FlightControls
  drove their local axis.
- Restored only the outer frames: `aileron_l` uses
  `Rotation=0,-145.4578340,-1.4633813` and `aileron_r` uses
  `Rotation=0,145.4578261,1.4633909`. The corresponding OBJ vertices and
  normals are inverse-compensated, so the neutral mesh remains in the original
  position while local-X animation follows the source diagonal hinge axes.
- Kept `elevator_l` and `elevator_r` unchanged from the v1.27.1 inner-surface
  repair: no static rotation, standard `NumberOfElevators=2`, local-X axis,
  and one FlightControls owner per physical surface.
- No gear, bay, material-island, weapon, sensor, carrier-recovery, or animation
  file was changed by this pass. Only the two outer-aileron OBJ blocks and the
  aircraft INI aileron sections were corrected.

v1.27.1 control-surface neutral-frame and carrier-interface correction
---------------------------------------------------------------------
- Removed the four accidental static `Rotation=` entries from the

v1.3 carrier alignment, terminology, and aircraft-entry revision
------------------------------------------------------------------
- F-35C performance-match diagnostic: copied the supplied F-35C
  `[FlightModel]`, `[Performance]`, and elevator-control interface values into
  the RQ-180 aircraft INI while retaining RQ-180 carrier geometry, models,
  weapons, and animations. This deliberately replaces the preceding RQ-180
  91000 N / 115-knot / 90-knot-stall test values to isolate aircraft-specific
  final-approach behavior. The RQ-180 control surfaces now use the F-35C
  `NumberOfElevators=2` interface with the audited local-X hinge axis. No
  RQ-180 OBJ or animation asset was changed.
- Follow-up carrier-approach test: the aircraft was observed deploying gear
  as it entered final approach and then failing to complete the final turn.
  Restored the previous `91000 N` per-engine thrust and retained the
  approximately 115-knot landing profile, while tightening low-speed heading
  capture with `BankGain=1.0`, `YawRateLimit=130`, `MaxRollForHeading=70`, and
  `MaxRollRate=120`. The normal small/large carrier patterns are unchanged.
- Follow-up performance test: raised both per-engine thrust fields to
  `105000 N` and changed the landing profile to `SpeedAndRange_Landing=0.175,0.40`,
  approximately 115 knots in the configuration's Mach-form speed entry. The
  minimum stall-speed field remains `StallSpeed=90`.
- Audited the source `elevator_l` and `elevator_r` mesh bounds and their
  aircraft instances. Their hinge direction is local X, their positions are
  symmetric about the centerline, and `Elevon1/2_RotationAxis=X` is retained;
  no extra static rotation or custom animation file change is required.
- Started from v1.2 as a separate test revision; the formal 1.0 package and
  earlier revisions are not overwritten.
- Matched the logical carrier recovery point's vertical datum to the deployed
  wheel datum: `LandingPivot=0,-0.0300,-0.0700`, while retaining the aft
  arresting position. The source OBJ has no physical arresting-hook mesh, so
  this remains a virtual point. This directly tests the deck-height mismatch
  seen during recovery.
- Restored the source `aileron_l`, `aileron_r`, `elevator_l`, and `elevator_r`
  flight-control bindings and reintroduced climb/descent pitch limits. The
  previous v1.3 draft left all control-surface counts at zero, which could
  make the AI overshoot the carrier's initial recovery pattern before it
  reacquired the local five-leg approach. Landing-gear and bay-door animation
  references are unchanged.
- Re-tuned the flight model for final-approach tracking: the high-speed combat
  gains are replaced by the proven stable flying-wing return-to-base values
  (`PitchGain=0.75`, `BankGain=0.40`, `MaxRollForHeading=45`, and
  `MaxRollRate=50`). The carrier's small/large/final pattern generation is not
  changed; this pass targets the aircraft leaving the correct final-approach
  line after the large pattern.
- Follow-up tuning after the first approach test: the 45-degree/50-degree-per-
  second roll limits did not let the aircraft complete the final turn. The
  current test uses an intermediate `MaxRollForHeading=60`, `MaxRollRate=85`,
  `BankGain=0.65`, and slightly higher heading response, while retaining the
  stable pitch and thrust response.
  OBJ, textures, gear, doors, wheel materials, and animation files are not
  changed.
- Removed the equipment-type words from the left side of sensor names. The
  game supplies the type label in the equipment list, so names now show only
  the designation; the explanatory descriptions remain intact.
- Rewrote the Chinese and English RQ-180 aircraft entries as aircraft-focused
  encyclopedia descriptions in the compact style used by the F-15EX entry.
  Package/install details are left in the README and are not repeated in the
  in-game aircraft description.
